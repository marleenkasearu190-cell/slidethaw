# 验收与最小修复

## 自动检查和人的判断分开

1. `validate_specs.py`：字段、源/资产哈希、路径范围、唯一 ID/名称、父关系、必需原生类型、删除授权、模板系列和有效内容集合。
2. `qa_compare_pptx.py`：按 presentation 的实际关系顺序定位 spec.editable_slide，不靠 slide 文件名字典序；检查页数与模式一致、精确绑定文本/单元格、实际原生类型、分组与连接器、资产、坐标、可检测隐藏/透明文字。双页模式额外检查原图页；单页模式拒绝多余原图页。
3. `office_render.ps1`：真实应用重开最终文件、渲染和有限的原生编辑行为。
4. `visual_diff.py`：并排/叠加/差分/重点区域；只生成诊断，不能把 SSIM、像素误差或“文本框很多”当成完成。
5. `--release`：结构检查、目标软件 receipt、review 状态和文件哈希，以及唯一最终输出。编辑测试 receipt 不得代替最终规范文件的渲染 receipt。

XML 不能判定字形被截断、复杂遮挡、白字白底、公式语义、字体替换后的可读性、全部图表底层数据。自动结构 PASS 必须标注 structural_only。未运行的渲染、视觉与编辑检查不能升级成 PASS。review 中的证据必须实际打开并观察，不能只是文件存在。

## 必查图像区域

查看最终可编辑页全尺寸及其与内部原图的对照，不得原图贴底。双页模式额外确认原图页完整无裁切无变形。关键区域标记 qa_region，查看中文标题换行、数字/负号/单位、公式分母和上下标、地图图例/坐标轴、箭头端点和底栏边界。单页模式仍须完成 reference_visual，不能把删除原图页当作取消原图对照。

如有原生图表，逐值核查数据、类别、系列、坐标和单位；没有源数据的图必须与真实图片对比，不数字化后冒称原始数据。复杂公式有原生要求时检查数学对象结构和实际修改，SVG/图片应列例外。

## 编辑及非目标保持

以规范文件为输入，新建临时编辑副本。改一处标题、移动一个实际存在的模块；有表格时修改一格。图表与数学对象测试按页面需求另行适配，未做就未做。

保留前后两版真实渲染；用 `visual_diff.py --baseline <改前可编辑页PNG>` 检查非目标区域（单页为 slide-1.png，双页为 slide-2.png）。比较必须相同渲染软件、版本、字体与画布。不要做自由形变配准来掩盖布局变化。授权重排区域按批准的目标规格验收，不要求与旧图逐像素相同。

检查并记录组内对象跟随、连接器路由正确、表格更新不破坏其他单元格、其他区域没有意外变化。当前脚本只确认记录的 COM 操作发生，不能自动证明这些视觉行为。

## 修复记录

在 qa/ 保存每轮日志：iteration、object_id、issue_type、severity、reference_evidence、render_evidence、allowed_patch、actual_patch、result。顺序：漏内容/改数 → 科学图/公式 → 裁切遮挡 → 模块位置 → 字体换行 → 装饰。

已通过模块冻结。每轮只改相关对象及必要相邻关系，重新导出新文件。建议 4 轮上限/2 轮无改善即诊断；达到预算仍有硬错误时保留 FAIL，不删数据、不额外光栅化以凑通过。

## 版本评测

正式批量替换前建议测试：长中文数字页、技术路线、地图分布、公式剖面、实验图表、授权删除重排，再加一张完全不同风格的科技封面，检查模板不会串用。

固定源图、字体、构建引擎、模型配置、目标应用与预算，分别比较内容错误数、科学图裁切数、遗漏、遮挡、编辑测试、非授权变更、人工修复时间。先满足内容和编辑性，再比较视觉与效率。软件烟测或合成回归用例通过，不称“历史科研页面质量全面提升”。
